# Отчет о тестировании: SauceDemo

**Дата:** 23.09.2026  
**Тестировщик:** Темур  
**Объект тестирования:** [saucedemo.com](http://saucedemo.com)

## Цель тестового цикла

Провести комплексную проверку основного пользовательского пути на SauceDemo (авторизация, каталог, корзина, checkout) в рамках функционального тестирования на standard\_user, а также целенаправленный поиск дефектов на специальных тестовых аккаунтах (problem\_user, performance\_glitch\_user), и на основе результатов дать рекомендацию по готовности продукта к релизу.

## Объем тестирования

В рамках цикла выполнено:

* Smoke-тестирование (сквозной путь пользователя)  
* Функциональное тестирование: авторизация (Login), корзина (Cart), оформление заказа (Checkout)  
* Целевой поиск дефектов на problem\_user и performance\_glitch\_user

**Вне рамок цикла:**

* Автоматизация  
* Кроссбраузерное/кроссплатформенное тестирование  
* Нагрузочное тестирование  
* Тестирование на locked\_out\_user, visual\_user

## Найденные дефекты

Дефекты найдены отдельно, в рамках целевого поиска на специальных тестовых аккаунтах (не на основном пути standard\_user). Полный список в saucedemo-bug-reports.csv.

| Severity | Количество |
| :---- | :---- |
| Critical | 2 |
| Major | 2 |
| Minor | 7 |
| Итого | 11 |

**Критичные (Critical):**

* Товар не добавляется в корзину (problem\_user)  
* Двойной подсчет Item Total на checkout (problem\_user)

**Существенные (Major, есть обходной путь):**

* Кнопка Remove не работает на странице каталога (problem\_user)  
* Поле Last Name не заполняется корректно (problem\_user)

**Незначительные (Minor):** сломанные изображения товаров, задержки при действиях под performance\_glitch\_user (логин, фильтрация, навигация), корзина не очищается после заказа.

## Риски

* Обнаруженные Critical-дефекты воспроизводятся только на problem\_user \- если этот аккаунт не отражает поведение продовой сборки, риск для реальных пользователей минимален; требуется уточнение у команды/заказчика.  
* Отсутствие автоматизации \- регресс перед следующим релизом потребует повторного ручного прогона всех 67 кейсов.

## Вывод

Продукт **готов к релизу** с точки зрения основного пользовательского пути \- 100% функциональных тест-кейсов пройдено, критичных дефектов на standard\_user не найдено.

Обнаруженные Critical-дефекты на problem\_user рекомендуется завести в баг\-трекер и уточнить их приоритет с командой перед релизом \- если problem\_user используется как реальный тип пользователя в продакшене, релиз до их исправления не рекомендуется; если это исключительно демонстрационный/тестовый аккаунт \- они не блокируют релиз.
